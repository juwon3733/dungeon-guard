# 06. 기술과 개발 순서

## 기술 구성 (안)
| 부분 | 기술 | 이유 |
|---|---|---|
| 메뉴 화면(던전, 편성, 도감, 지도, 장부) | React 19 + Astryx | 표·목록·탭·툴팁이 많은 경영 화면에 맞음 |
| 공성전 화면 | Canvas 2D (필요하면 PixiJS) | 수십 마리 실시간, 이펙트 |
| 빌드 | Vite | Astryx(React) 사용 때문에 필요 |
| 규칙 | 순수 TS 모듈(화면과 분리) | Node에서 공성 시뮬레이션으로 밸런스 확인 |
| 데이터 | `src/data/*.ts` (몬스터, 성채, 지역, 시설) | 엔진은 데이터만 읽음 |
| 저장 | 브라우저 저장소(버전 번호 + 이전 규칙) | 나중에 서버 저장 추가 가능 |
| 배포 | GitHub Pages(정적) | 기존 방식 유지 |

정할 것: Astryx(React+빌드)로 갈지, 기존 프로젝트처럼 빌드 없는 순수 JS로 갈지. 메뉴가 많아서 Astryx 쪽을 권한다.

M1과 M2가 재미의 핵심이라 가장 먼저, 가장 오래 다듬는다. 그림(M0)은 개발과 같이 진행한다.

## 시뮬레이션 기준 (M1부터)
- 성채마다 "권장 부대"로 자동 공성 승률 60~80%, 지휘 효과를 맞추면 90% 이상.
- 같은 전투력이라도 지휘 효과가 성채와 안 맞으면 40% 이하 → 판단이 의미 있는지 확인.
- 신화 하나로 모든 성채가 쉬워지지 않게(신화 1부대 + 일반 병력만으로 장 보스 승률 50% 이하).

## 진행 기록

### M1 공성전 코어 — 완료 (games/siege)
- 엔진·시뮬레이션·Astryx 편성 화면·Canvas 횡스크롤 화면.
- 시뮬레이션(`npm run sim`) 결과(국경 요새): 편성별 한계 수비 배율 0.8~1.35, 지휘 효과 이득 +4~17%.
  - 성벽 넘기가 가장 빠르고(약 76초, ★2.2), 지하 침투가 가장 단단하며(한계 1.35), 정문 힘싸움은 느리지만 안정.
  - 부대를 세 갈래로 나누면 각개 격파당해 약하다(한계 0.81).
- 발견: 오우거(성문 피해) 효과 이득이 0%. 성문을 일찍 부수면 망루가 살아 있는 채로 정문 수비대가 쏟아져 나와 정면전이 되기 때문.
  → "망루 먼저, 성문은 나중" 공략이 생김. M2에서 **성문 공격 대기/시작 명령**을 넣어 플레이어가 타이밍을 잡게 한다.

### M2 부대 명령과 부대장 스킬 — 완료
- 부대 명령: 전진/정지, 성문 공격/대기(정문 부대), 후퇴. 전투 화면 아래 부대 패널 버튼.
- 부대장 고유 스킬 12종(영웅 이상, `src/data/monsters.ts`의 `SKILLS`): 땅울림, 망자 일으키기, 매혹, 박쥐 떼, 돌진, 검은 방패, 저주 구름, 피의 연회, 썩은 숨결, 지옥불 투석, 노래, 종말의 불. 숫자 키 1~3, 스페이스는 일시정지.
- 스킬을 쓰면 전투가 멈추고 컷인(등급 색 사선 띠, 큰 부대장, 스킬 이름) → 스킬별 이펙트.
- 엔진에 기절, 받는 피해 증가, 부대 피해 감소, 예약 타격(타이머) 추가.
- 시뮬레이션(`npm run sim`)은 운영 방식 3가지(방치/스킬 자동/스킬+성문 대기)로 한계 배율을 비교한다.
  - 국경 요새: 스킬로 한계 배율 +4~31%. 리치(해골 소환)가 가장 크다(1.23 → 1.61) → 성채가 늘면 다시 맞춘다.
  - "망루가 무너질 때까지 성문 대기"는 정문 쪽에 사격 부대가 있을 때만 이득. 없으면 성 안쪽 망루를 못 부숴 손해(0.89 → 0.55였다).

### M3에서 할 것
- 성채 2~3개 추가: 지휘 효과·스킬마다 빛나는 성채(망루가 많은 성, 지하가 없는 바위 요새, 해자가 넓은 수상 성채)
- 리치 등 스킬 이득 다시 맞추기, 몬스터 30종 모두 공성 시뮬레이션에 넣기
- 그림이 오면 연결(있는 것부터)

### (이전 계획) M2에서 할 것

- 부대 명령: 성문 공격 대기/시작, 목표 바꾸기(망루·성문·핵심), 레인 전환 지점 이동
- 부대장 고유 스킬(영웅 이상) + 컷인·이펙트
- 오우거 효과 재측정, 성채 2~3개 추가해 지휘 효과마다 빛나는 성채 만들기
