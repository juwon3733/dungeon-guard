# 몬스터 설계

타워 대신 몬스터를 뽑아 설치하고 합치며 용사를 막는 랜덤 디펜스다. 2026-11-06 사용자 결정 기준이며, 수치는 플레이 후 고칠 초안이다. 계획서의 시설 설계, 층 보상 덱을 대체한다.

## 확정된 것

- **시작:** 마왕과 유물만 고른다. 유물은 시작할 때만 고른다(유물 칸 0개로 시작해 메인 스토리를 깨며 최대 3개). 판 중에는 유물을 얻지 않는다.
- **해금:** 영혼석으로 사지 않는다. 메인 스토리 스테이지를 처음 깰 때 마왕, 유물, 유물 칸이 차근차근 풀린다(2026-11-07 사용자 결정, 아래 메인 스토리).
- **뽑기:** 골드로 몬스터를 1마리씩 소환하면 맵의 빈 길 옆 칸에 바로 나온다. 대기 칸은 없다. 맵에 둘 수 있는 수에 상한이 있어 합치기로 자리를 만든다. 대량 소환(연속, 10연)은 하지 않는다. 3택 소환은 기본 소환에서 뺐고, 비싼 특별 소환 후보로 남긴다.
- **제물:** 몬스터를 끌어 왕좌의 마왕 위에 놓아 바치면 마왕 체력 회복과 번개 재사용 대기 감소를 함께 얻는다. 등급별 표와 랭크 보정은 `js/data/monsters.js`의 `SACRIFICE_RULES`(구현됨, 수치 초안).
- **보스 보상:** 마지막 웨이브가 아닌 보스(스토리 없는 판의 5번째 웨이브 대마도사. 6스테이지 스토리는 보스가 마지막 웨이브에만 있다)를 잡으면 그 웨이브가 끝나고 준비 단계에서 3택을 띄운다. 희귀·영웅 몬스터 1장(영웅 40%, 전설과 히든 전용 제외), 희귀·영웅 장비 1장(영웅 40%), 300G 1장. 고르기 전에는 준비 시간과 다음 웨이브, 소환과 끌기가 멈추고, 몬스터는 맵의 빈 칸에 바로 나온다. 상한이 차면 몬스터 카드가, 보관함이 가득 차면 장비 카드가 꺼진다. 수치는 `js/data/monsters.js`의 `BOSS_REWARD_RULES`(구현됨, 수치 초안).
- **설치:** 모든 몬스터는 길 옆 칸에만 설치한다. 길 칸에는 설치하지 못한다.
- **전투:** 근접 몬스터는 설치한 칸에서 길로 나가 용사를 막고, 쓰러지면 설치한 칸에서 다시 나온다. 원거리 몬스터는 설치한 칸에서 공격한다.
- **합치기:** 같은 몬스터를 모으지 않는다. 아래 세 가지를 쓴다.
- **몬스터 수:** 전체 도감은 크게 두고, 판마다 그중 일부가 나온다.
- **마왕:** 몬스터를 제한하지 않는다. 전용 몬스터로 개성을 낸다.
- **진영 시너지:** 사용자 지시로 일단 뺐다(2026-11-07). 진영은 분류로만 둔다.
- **타락:** 사용자가 생각보다 별로라고 해 일단 끈다(2026-11-07). 코드는 남겨 `CORRUPTION_ENABLED`로 되살릴 수 있게 한다.

## 합치기

| 방식 | 규칙 |
|---|---|
| 등급 합치기 | 같은 등급 아무 3마리(`MERGE_RULES.gradeCount`)를 합쳐 상위 등급 무작위 1마리(2026-11-07 사용자 결정, 2마리에서 바꿈) |
| 조합식 | 특정 몬스터 둘을 합치면 정해진 몬스터. 도감에 공개. 조합식이 맞으면 등급 합치기보다 먼저 |
| 히든 조합식 | 조건까지 맞으면 나오는 숨은 조합(재료 2마리). 도감에 `???` |

조작(구현됨): 몬스터를 끌어 다른 몬스터 위에 놓아 합친다. 결과는 놓은 칸에 남고 다른 재료 칸은 비어 다시 쓸 수 있다.

- **셋째 재료:** 끌기 시작할 때 같은 등급 중 랭크가 낮고, 장비가 없고, 끄는 몬스터와 가까운 순으로 자동으로 정한다(`Game.mergeCandidates`). 끄는 동안 재료에 고리와 결과 칸으로 잇는 선, 놓을 곳 위에 결과("3마리 합치기 → 영웅 무작위")와 이어받을 장비를 보여 준다.
- **재료 교체:** 놓기 전에 같은 등급 몬스터 위에 올렸다가 다른 몬스터로 옮기면 먼저 올린 몬스터가 셋째 재료가 된다. 셋째 재료 위에 올리면 그 몬스터가 놓을 대상이 되고 셋째는 다른 몬스터로 바뀐다.
- **거절:** 같은 등급이 3마리 미만이면 "같은 희귀 3마리가 있어야 합칩니다(지금 2마리)"처럼 안내만 한다.
- **팝업 합치기 버튼:** 누른 몬스터 칸에서, 같은 판단으로 고른 같은 등급 2마리와 합친다(조합식은 보지 않는다). 합칠 수 없으면 꺼져 있고 누르면 까닭을 알려 준다.
- **승계:** 랭크는 재료 중 가장 낮은 값, 장비는 가장 좋은 것 하나(같으면 끌어온 쪽, 놓은 쪽, 셋째 순)를 잇고 나머지는 보관함으로(가득 차면 30G).
- **행동 함수:** 끌어 놓기, 팝업 버튼, 소환, 판매, 제물, 옮기기는 `Game.act({ kind, ... })` 하나를 거친다. 뒤에 고정 난수와 입력 기록을 여기에 넣는다.

## 분류

**역할**

| 역할 | 하는 일 | 설치 위치 |
|---|---|---|
| 탱커 | 길로 나가 막고 오래 버팀 | 길 옆 |
| 근접 공격 | 길로 나가 막으면서 강하게 때림 | 길 옆 |
| 원거리 단일 | 앞선 용사 하나 집중 | 길 옆 |
| 원거리 광역 | 무리 공격 | 길 옆 |
| 지원 | 감속, 회복, 버프 | 길 옆 |

**진영:** 언데드, 오크, 악마, 야수, 정령. 마왕마다 잘 맞는 진영이 있다.

**등급(`MONSTER_GRADES`, 구현됨, 2026-11-07 사용자 결정)**

| 등급 | 소환 | 합치기로 얻기 | 맵 제한 | 제물(체력, 번개) | 판매 |
|---|---|---|---|---|---|
| 일반 | 70% | | 없음 | +1, -2초 | 20 |
| 희귀 | 25% | 일반 3마리 | 없음 | +2, -5초 | 60 |
| 영웅 | 5% | 희귀 3마리 | 없음 | +5, -10초 | 150 |
| 전설 | 없음 | 영웅 3마리, 조합식 | 없음 | +10, -30초 | 300 |
| 신화 | 없음 | 전설 3마리, 히든 조합식 | 1마리 | +20, -60초 | 800 |

- 소환 확률은 `SUMMON_RULES.odds`, 판매는 `SUMMON_RULES.refund`, 제물은 `SACRIFICE_RULES`, 맵 제한은 등급의 `fieldMax`다. 전설의 맵 1마리 제한은 없앴다(표의 "없음").
- 등급 표의 `summon: false`(전설, 신화)는 소환과 보스 보상 후보(`gradePool`)에서 빠지고, 등급 합치기 결과 후보(`mergePool`)에는 들어간다. 그래서 영웅 3마리가 전설 3종 중 하나(겹칠 수 있음)가 된다. 몬스터에 `gradeMerge: false`를 적으면 조합식으로만 얻는다.
- 다음 등급에 후보가 없으면 그 등급이 최고 등급이라 등급 합치기를 할 수 없다(`nextGrade`). **신화 몬스터는 다음 작업이다.** 지금은 표에 없어 전설이 최고 등급이고, `MONSTERS`에 `grade: 'mythic'` 항목을 넣으면 전설 3마리 합치기와 히든 조합식 결과로 바로 동작한다. 시험(`tools/smoke.js`)과 캡처 장면 `mythic`은 시험용 신화 항목을 잠깐 넣어 확인한다.
- 신화 색은 붉은 무지개(`rainbow`): 등급 테두리, 맵 등급 마름모, 합치기 빛줄기와 불꽃이 붉은색, 주황, 노랑, 분홍으로 흐른다. 연출 세기는 등급의 `fx`(0 보통, 1 영웅, 2 전설, 3 신화)로 정해 신화의 이름 글자, 빛줄기(`GRADE_FX.mythic`), 히든 발견 연출이 전설보다 크고 길다.
- 도감 조합식 탭은 등급의 `secret`(전설, 신화) 결과를 찾기 전까지 `?`로 둔다.

| 등급 | 차이(초안) | 판별 풀 목표 |
|---|---|---|
| 일반 | 기본 수치만 | 8종 이상 |
| 희귀 | 능력 1개 | 12종 |
| 영웅 | 능력과 고유 효과 | 15종 |
| 전설 | 판도를 바꾸는 패턴 | 후보 대부분 |
| 신화 | 전설 위 최상위, 맵에 1마리 | 다음 작업 |

전체 도감 목표는 100종 이상이다. 마왕마다 전용 몬스터 5종 초안.

## 랭크

등급은 몬스터 종류에 고정이고, 랭크는 개체의 성장이다.

- **단계:** D, C, B, A, S. 발밑 등급 표식 옆에 글자로 표시한다(D는 표시하지 않고 S는 금색). 수치는 `js/data/monsters.js`의 `MONSTER_RANKS`, `RANK_KILL_XP`(구현됨).
- **올리는 법:** 처치 경험치로만 오른다. 같은 종 합치기로 올리지 않는다.
- **효과 초안:** 랭크마다 체력과 피해 약 25% 증가, S에서 능력 강화.
- **합칠 때:** 재료 중 가장 낮은 랭크를 결과가 이어받는다(구현됨).
- **조합식 조건:** 재료별 최소 랭크를 적을 수 있다. 조건이 안 맞으면 평소 규칙대로 합쳐진다(구현됨). 첫 전설 죽음의 군주가 이 조합식으로 나온다(영웅 3마리 등급 합치기로도 나올 수 있다).

```js
{ a: 'bone_knight', aRank: 'A', b: 'curse_shooter', bRank: 'A', result: 'death_lord', hidden: true }
```

## 장비

얻은 장비를 어느 몬스터에게 줄지 고민하게 만드는 기능이다(구현됨). 16종 표는 `js/data/monsters.js`의 `EQUIPMENT`, 얻는 확률과 보관함은 `EQUIP_RULES`(수치 초안). 그림은 `assets/sprites/equip_<id>.png`(48px).

- **등급과 효과:** 일반 6종, 희귀 5종, 영웅 5종. 효과는 체력, 피해, 공격 속도, 사거리, 처치 경험치의 비율 증가이고, 몬스터 수치 계산(`monsterStats`) 한 곳에서 랭크 배율 뒤에 곱한다. 공격 속도는 공격 간격을 나눈다.
- **얻는 법:** 보스 보상 3택은 몬스터 1장, 장비 1장(희귀 또는 영웅, 영웅 40%), 골드 1장이다. 정예 용사를 처치하면 25% 확률로 장비를 떨어뜨린다(일반 75%, 희귀 25%).
- **보관함:** 하단 바에 6칸이 늘 보인다. 가득 차 있으면 들어올 장비는 30G로 바뀌고 글자로 알린다. 보상의 장비 카드는 꺼진다. 다시 시작하면 비우고 영구 저장은 하지 않는다.
- **끼우기:** 몬스터당 1칸. 보관함의 장비를 맵의 몬스터 위로 끌어 놓는다(웨이브 중에도). 끼고 있으면 맞바꿔 원래 장비가 보관함으로 돌아간다. 체력 효과가 바뀌어도 현재 체력은 비율을 유지한다. 팝업에서 뺄 수 있다(보관함이 가득 차면 못 뺀다).
- **합치기, 제물, 판매:** 합치면 재료(등급 합치기는 3마리)의 장비 중 등급이 가장 높은 것 1개가 결과로 이어진다(같으면 끌어온 쪽, 놓은 쪽, 셋째 순). 나머지와 제물·판매한 몬스터의 장비는 보관함으로 돌아가고, 자리가 없으면 30G로 바뀐다.

## 마왕과 유물

판을 시작하기 전 선택 화면에서 마왕 1명과 유물을 고른다(구현됨). 표와 수치 초안은 `js/data/demonlords.js`.

- **흐름:** 스토리 스테이지마다 시작 전 대화 뒤에 고르기 화면이 나온다(아래 메인 스토리). 쓸 수 있는 마왕이 하나이고 고를 유물이 없으면 건너뛴다. 직전 선택은 `localStorage`(`dungeonGuard.loadout`)에 남기고, 읽지 못하면(`file://` 등) 기본 선택(균열의 군주, 유물 없음)이다. 잠긴 것은 기본값으로 돌린다.
- **효과 키:** 마왕과 유물은 같은 효과 키(`LORD_EFFECTS`)를 쓴다. 한 판의 효과는 `Game.mods`에 합쳐 두고(더하는 키는 더하고 곱하는 키는 곱한다) 각 계산 지점이 읽는다. 코드에 마왕이나 유물 이름별 분기를 두지 않는다. 값이 없으면 효과가 없다(`tools/simulate.js`와 시험 도구의 기본).

| 키 | 뜻 |
|---|---|
| startGold | 시작 골드 더하기 |
| maxHp | 마왕 최대 체력 더하기(빼기 가능) |
| skillCooldown | 번개와 호통 재사용 대기 곱 |
| lightningDamage | 번개 피해 곱 |
| heroSpeed | 용사 이동 속도 곱 |
| damage, hp, attackSpeed, range | 몬스터 수치 비율. `monsterStats`에서 장비 다음에 곱한다 |
| xp | 처치 경험치 비율 |
| bounty | 처치 골드 곱(반올림) |
| rareChance | 소환 희귀 확률 더하기(일반에서 뺀다) |
| summonBase | 소환 시작 비용 더하기(상한은 그대로) |
| fieldMax | 맵 몬스터 상한 더하기 |
| respawn | 막는 몬스터가 쓰러졌다 다시 나오는 시간 곱 |
| eliteDrop | 정예 장비 드롭 확률 더하기 |
| refund | 판매 환불 곱(반올림) |
| sacrifice | 제물 효과 곱(체력은 내림) |

**마왕 3명(`DEMON_LORDS`).** 스킬은 셋 다 번개와 호통이다. 새 마왕 그림은 1장이라 왕좌의 대기와 주문 자세에 같은 그림을 쓰고, 주문 때는 어두워진 화면 위로 빛과 함께 떠오른다. 그림은 128px를 2배로 그린다. 체력 막대의 초상, 대사(공통 대사에 마왕별 3줄을 더한다), 마왕 탭의 호통 초상(그림의 머리 부분을 잘라 씀), 결과 화면도 고른 마왕을 따른다.

| id | 이름 | 그림 | 효과 | 성격 |
|---|---|---|---|---|

## 메인 스토리와 해금

메인 스토리를 진행하면서 마왕과 유물이 차근차근 해금된다(2026-11-07 사용자 결정, 구현됨, 수치 초안). 영혼석과 가격, 칸 사기는 없앴다. 지금은 맵 하나로 돌고, 스테이지별 새 맵과 그림은 다음 단계다.

**방향(2026-11-07 사용자 결정):** "메인 스토리는 금방 다 해금이 가능하게 해 놓고, 콘텐츠를 메인으로 랭킹도 경쟁하고 싶다." 메인 스토리는 튜토리얼처럼 6스테이지로 빠르게 끝나고, 게임의 중심은 본부의 도전의 문(콘텐츠)이다. 도전의 문은 스토리를 다 깨지 않아도 처음부터 들어가고, 콘텐츠마다 열리는 스테이지(`HQ_CONTENTS[].unlockStage`)를 둔다. 콘텐츠와 랭킹은 아직 없다.

- **흐름:** 타이틀(시작하기, 기록이 있으면 이어하기) → 본부 → 작전 테이블(스토리 지도) → 스테이지 선택 → 시작 전 대화 → 마왕과 유물 고르기(쓸 수 있는 마왕이 하나이고 고를 유물이 없으면 건너뜀) → 전투 → 승리 대화 → 해금 카드(처음 깰 때만) → 결과 화면(다음 스테이지는 바로 그 스테이지 대화로, 본부로). 지면 결과 화면에서 다시 도전(대화 없이 바로) 또는 본부로. 스토리 지도와 결과 화면의 Esc도 본부로 간다. 깬 스테이지는 다시 할 수 있고 대화는 건너뛸 수 있다. 해금은 처음 깰 때만 준다.
- **대화:** 클릭 또는 Space로 넘기고 Esc(또는 건너뛰기 버튼)로 건너뛴다. 글자는 초당 40자씩 나오다가 누르면 끝까지 나온다. 맵 위를 어둡게 덮고 아래쪽 양피지 대화창에 왼쪽 초상(밀랍 액자)과 이름표. 초상은 표의 그림을 잘라 쓴다(마왕 3명, 고블린 창병, 전사, 대마도사, 부대장). 예전 타이틀의 긴 설명은 1번 스테이지 대화(소환, 합치기, 번개와 호통)와 판 중 안내 쪽지(소환, 합치기, 제물, 장비, 번개)로 옮겼다.
- **표:** `js/data/story.js`의 `STORY_TITLE`, `STORY_CAST`, `STAGES`. 장 구분은 없앴다. 스테이지마다 id, 번호, 이름, 웨이브 목록(`WAVES` 인덱스, 겹쳐도 된다), 보스 덮어쓰기, 체력 배율, 시작 골드 보너스, 지도 자리, 시작 전 대화, 승리 대화(각 2~4줄), 해금 목록을 적는다. 코드에 스테이지별 분기는 없다.
- **웨이브:** `stageWaves`가 `WAVES` 항목을 복사해 쓴다(표에 없는 값은 그대로). `noBoss`는 고른 웨이브의 보스 칸을 비우고("보스 없는 표"), `boss`는 마지막 웨이브의 보스 칸을 덮어쓴다. 6스테이지 표는 중간 보스 웨이브(인덱스 4)를 쓰지 않아 보스는 3·5·6번의 마지막 웨이브에만 있고, 마지막 보스는 보상 없이 승리로 끝난다. 마지막 웨이브가 아닌 보스의 보상 3택 규칙은 스토리 없는 판(웨이브 표 전부)에서 그대로다. 용사 체력은 원래 웨이브 단계(`level`, `hpPerWave`)에 스테이지 배율(`Game.heroHpMul`)을 곱한다.
- **열림:** 1번은 처음부터, 다음 스테이지는 이전 스테이지를 깨면 열린다. 처음에는 균열의 군주만 있고 유물 칸은 0개다.

- **이야기:** 주인공은 던전을 막 분양받아 입주한 균열의 군주, 곁에는 잔소리꾼 부하 고블린 창병 꼬챙이. 2번에서 벽 너머 목소리로 나온 뼈의 여왕이 3번에서 함께 싸우고 동료가 된다. 4번에서 분양 대금을 받으러 온 황금 마왕이 5번에서 편을 든다(끝까지 이자를 따진다). 6번에서 부대장 그라벨이 사실 던전 후기를 쓰러 왔다는 엔딩으로 끝나며 "도전의 문"으로 이어 준다. 다른 인물은 견습 용사 덕수, 대마도사 몽글.
- **저장:** `js/game/meta.js`의 `Meta`. `localStorage`의 `dungeonGuard.meta` 한 칸에 버전 번호(지금 3)와 함께 JSON으로 둔다. 내용은 깬 스테이지 목록, 본 몬스터, 찾은 조합식(공개와 히든, `recipeKey`), 얻은 장비(무기고), 판 수, 승리 수, 최고 스테이지. 마왕, 유물, 유물 칸의 해금 여부는 저장하지 않고 깬 스테이지에서 계산한다(`hasLord`, `hasRelic`, `relicSlots`). 버전 2(12스테이지) 저장은 깬 스테이지와 최고 스테이지를 새 표로 옮긴다(옛 번호 N → 새 번호 ceil(N / 2), 옛 표에만 있던 s7~s12도 버리지 않는다). 버전 1 저장을 읽으면 본 몬스터, 조합식, 판 수만 옮기고 산 항목과 영혼석은 버린다. 읽기와 쓰기는 모두 try/catch로 감싸 저장소가 없거나(`file://`) 막히거나 값이 이상하면 초기값으로 돈다. 모르는 id와 겹친 id는 버린다. `tools/simulate.js`와 `tools/smoke.js`는 저장소 없이 메모리의 초기값으로 돌고, 캡처는 새 브라우저 페이지의 저장소를 비우고 시작한다.
- **장비 기록:** 판에서 얻은 장비(정예 드롭, 보스 보상, 보관함이 가득 차 골드로 바뀐 것 포함)를 `Meta.seeEquip`이 한 번씩 남긴다. 본부 무기고가 보여 준다.
- **스토리 없는 판:** `Game.reset(loadout)`처럼 스테이지 없이 부르면 `WAVES` 전부를 체력 배율 1, 골드 보너스 없이 돈다. `tools/simulate.js`와 시험 도구가 쓴다.
- **화면:** 재질은 `docs/ART_BIBLE.md`.
  - 본부: 아래 "본부".
  - 스토리 지도: 커다란 양피지 지도에 이야기 제목, 6개 도장과 점선 길. 깸은 붉은 밀랍, 열림은 밝게(다음 스테이지는 숨쉬는 붉은 고리), 잠김은 어둡게 자물쇠. 아래 나무판에 고른 스테이지의 이름, 웨이브 수, 보스, 처음 깰 때의 보상 아이콘과 출전 버튼(깬 스테이지는 다시 하기). 좌우 화살표로 고르고 Enter로 출전, Esc와 오른쪽 위 버튼은 본부로.

- **느낌표:** 새로 볼 것(다음 스테이지, 새 해금, 새로 본 몬스터와 조합식, 새 장비, 새로 열린 콘텐츠)이 있는 시설에 붉은 밀랍 느낌표. 시설마다 `news()` 값을 들어갈 때 기억해 두고 값이 바뀌면 다시 단다. 본 값은 게임 기록과 따로 `localStorage`의 `dungeonGuard.hqSeen`에 둔다(못 읽으면 처음 상태).
- **고블린 비서 말풍선:** 진행(깬 스테이지 수)에 따라 다음 할 일을 짧게(`HQ_GOBLIN_LINES`, `{no}`·`{name}`은 다음 스테이지). 다 깨면 도전의 문을 권한다.
- **위쪽:** 왼쪽 표지판(마왕군 본부, 스토리 n/6), 오른쪽 소리와 설정(소리, 효과 줄이기, 타이틀로).

- **히든 발견:** 몬스터 팝업의 조합 표시와 발견 연출은 그대로다. 연출은 기록에 처음 남을 때만 나오고 다시 찾아도 기록은 한 번만 남는다.

### 능력 종류 (`ABILITY_KINDS`, 구현됨)

몬스터의 `abilities`에 `{ kind, ...값 }`으로 적는다. 코드는 몬스터 id가 아니라 kind로 동작하고, 팝업·도감·보상 카드의 설명 문구도 이 표의 `desc`가 만든다.

| kind | 값 | 동작 |
|---|---|---|
| enrage | below, intervalMul | 체력 비율이 below 이하면 공격 간격 곱 |
| curseShot | duration, takenMul | 맞은 용사가 받는 피해 곱. 겹치지 않고 시간 갱신 |
| deathStun | radius, duration | 쓰러질 때 반경 안 용사 기절(보스 제외) |
| burnShot | dps, duration | 맞은 용사가 0.5초마다 지속 피해(방어력 무시). 겹치지 않고 시간 갱신. 화상으로 쓰러뜨리면 건 몬스터가 처치 경험치 |
| slowShot | speedMul, duration | 맞은 용사 이동 속도 곱. 시간 갱신, 배율은 더 느린 쪽 |
| stunShot | chance, duration | 맞을 때 확률로 기절. 보스는 걸리지 않고 난수도 쓰지 않는다 |
| lifesteal | ratio | 준 피해(방어력 뺀 뒤)의 비율만큼 회복, 최대 체력까지 |
| regen | perSec | 쓰러지지 않은 동안 초당 회복 |
| aura | stat, radius, value | 반경 안 몬스터(자신 포함)에게 heal(초당 회복), damage(피해 비율), attackSpeed(공격 속도 비율). 같은 stat은 가장 큰 값 하나만. 쓰러진 몬스터는 내지도 받지도 않는다. 피해와 공격 속도는 `monsterStats`에서 곱하고 최대 체력은 바꾸지 않아 체력 비율이 흔들리지 않는다 |

| chain | count, ratio, jump | 맞은 용사에서 jump칸 안의 다음 용사로 count번 이어지며 피해 비율(이미 맞은 용사는 건너뛴다) |
| goldOnKill | gold | 쓰러뜨리면 처치 골드와 따로 골드 |
| burnGround | radius, dps, duration | 광역 공격이 떨어진 자리에 장판(`Game.hazards`), 0.5초마다 방어력 무시 피해 |

**지원 역할(`support`):** 막지 않고 놓은 칸에 서서 약하게 쏘며 오라를 낸다. 발밑에 오라 종류 색의 작은 룬 고리가 돌고, 오라 범위 원은 몬스터를 고르거나 끌 때만 보인다.

**투사체 모양:** 표의 `art.shot`(pixelfx 투사체 시트 열쇠 또는 `bolt`), 광역 폭발은 `art.impact`. 없으면 화살과 보라 마력 구체.

## 운 보정 초안

다시 뽑기와, 일정 횟수마다 확정 등급을 넣는다. 수치는 시험 뒤 정한다.

## 데이터 구조

몬스터와 조합식은 표에 한 줄을 추가하면 들어가게 만든다. 코드에 몬스터 이름별 분기를 두지 않는다. 능력은 재사용 가능한 능력 종류와 값으로 적는다. 수치 초기값은 역할과 등급별 공식으로 낸다.

```js
{ id: 'skeleton_archer', name: '스켈레톤 궁수', role: 'ranged', faction: 'undead', grade: 'common',
  sprite: 'pl_mon_skeleton_archer', stats: { hp: 40, damage: 8, interval: 0.8, range: 3 }, abilities: [] }
{ a: 'skeleton_archer', b: 'dark_mage', result: 'curse_shooter', hidden: false }
```

## 만드는 순서

1. **전환:** 시설을 몬스터로 바꾸고 데이터 틀을 만든다(진행 중).
2. **뽑기와 합치기 시험:** 마왕 1명, 몬스터 6~8종, 조합식 3~4개(완료). 사용자가 플레이해 재미를 판단한다.
3. **판 중 선택:** 맵에 바로 나오는 소환, 제물, 보스 보상 3택(완료).
4. **고유 능력, 랭크(완료), 랭크 조건 히든 조합식(완료), 장비(완료), 등급 연출.** 등급 5단계(신화 추가)와 3마리 등급 합치기(2026-11-07, 완료). 다음: 신화 몬스터를 표에 넣기.
5. **마왕과 유물 선택 화면(완료), 영구 수집과 도감(완료).** 영혼석 해금은 메인 스토리 해금으로 바꿨다(2026-11-07).
6. **몬스터 확장.** 공통 풀 16종을 더해 23종, 능력 종류 14개(2026-11-06, 수치 초안). 마왕별 전용은 다음 묶음이다.
7. **메인 스토리 1부(완료, 맵 하나).** 6스테이지(튜토리얼처럼 빠르게), 대화, 스토리 지도, 해금 카드, 본부. 다음: 도전의 문 콘텐츠와 랭킹, 스테이지별 새 맵과 그림.

여러 갈래 길은 입구 둘(합류형)로 넣었다(2026-11-06, `docs/MULTI_PATH.md` 구현 상태). 모든 몬스터 규칙은 그대로이고, 막는 몬스터는 가장 가까운 갈래로 걸어 나가며 원거리 몬스터는 남은 거리가 가장 작은 용사를 노린다. 분기형은 아직 없다. 웨이브 보상 3택 같은 판 중 강화는 시험 뒤 성장 재미가 부족할 때 유물과 겹치지 않게 추가한다. 밸런스는 마지막에 천천히 한다.

## 라운드와 소환 강화 (2026-11-07 사용자 결정)

- **스토리:** 6장을 각각 한 판으로 진행한다. 1장 10라운드, 2장 20라운드 ... 6장 60라운드. 모두 1라운드부터 시작한다.
- **라운드:** 한 라운드 30초, 보스 라운드 45초. 시간이 끝나면 못 잡은 용사를 남긴 채 다음 라운드가 시작된다. 다 잡으면 3초 뒤 시작한다. 일찍 끝내거나 다음 라운드를 부르면 남은 시간만큼 골드를 받는다. 배속은 1, 2, 3배.
- **정예와 보스:** 정예는 3라운드와 5라운드마다, 보스는 10라운드마다(대마도사, 부대장 번갈아).
- **카드 보상:** 5라운드마다, 그리고 보스를 잡으면 3택. 고르는 동안 전투가 멈춘다. 표는 `BOSS_REWARD_RULES.roundEvery`.
- **소환 강화:** `SUMMON_LEVELS` 7단계. 판 안에서만 유지되며 높은 단계에서는 전설도 소환된다. 신화는 소환되지 않는다.
- **유물:** 최대 4개를 들고 간다. 칸은 1, 4, 5, 6장을 처음 깰 때 풀린다.
- **중간 저장:** 라운드가 넘어갈 때 저장하고 본부에서 이어한다(`Game.saveRun`, `loadRun`). 전투 중 용사는 저장하지 않는다.
- 봇 측정: `node tools/simulate.js [판 수]`. 60라운드가 약 25분이고 합치는 봇은 체력 손실 없이 이긴다. 아직 쉬우니 나중에 맞춘다.
