## 현재 상태

- 품질 시험판이 동작한다. `index.html`을 바로 열면 실행된다.
- 자동 시험: `node tools/simulate.js`, `node tools/smoke.js`
- 사람이 끝까지 플레이한 검증과 소리 확인은 아직 없다. 난이도도 자동 조작 기준이다.
- 그림 정의는 `js/data/balance.js`의 `HEROES[..].anim`, `ORC_ART`, `FACILITY_ART`에 있다. 동작, 프레임 수, 방향(`dirs`), 캔버스 안 발끝 높이(`footPx`)를 적는다. 도적, 마법사, 오크는 서쪽을 동쪽 그림의 좌우 반전으로 쓰고, 사망은 남쪽 하나만 쓴다(오크는 시체가 없어 사망 동작이 없다).
- 캐릭터 ID: 전사 `ddc0a339-b2b7-4527-b99e-afa2b49adf31`, 도적 `8add0349-f88f-4986-832c-aa1de801f1b8`, 마법사 `c7cbdf3a-d509-4366-9658-cf3c19cdcc36`, 오크 `6179cae3-778a-420a-977c-6d9c1400dafb`.
- 동작 방식: 템플릿 동작은 무기가 사라져 쓰지 않는다. 걷기는 `skeleton-v3`(1방향 3회), 공격과 사망은 `v3` 직접 설명(1방향 1회)이다. 전사의 사망만 먼저 만든 `skeleton-v3` 4방향이다.
- `facility_archer.png`와 멧돼지 전사 그림은 지웠다. Asteria 직업 그림(`swordsman`, `beast_tamer`, `stormcaller`)과 `boss_*` 그림은 정예몹과 보스 후보라 파일을 남겨 두었지만, 지금 쓰지 않는 것은 불러오기 목록에서 뺐다. 정예몹을 넣을 때 `js/core/assets.js`에 다시 추가한다. `render.js`의 Asteria 그림 처리와 `HERO_SCALE`도 정예몹용으로 남겨 두었다.
- 칸 72px로 확정했다(커밋 안 함): `js/core/config.js`의 `WORLD_ZOOM` 0.75로 세계만 줄여 그린다. 코드 안의 칸은 그대로 96 단위이고, 한 화면이 26x15칸, 길 50칸(이전 35칸), 길 폭 120, 건설 칸 132개(이전 63개, 길에서 2칸 거리까지)다. 전사는 화면에서 1.5배로 보여 도트 크기가 조금 불균일하다. 시설은 화면에서 원본 1배라 도트가 깨지지 않는다. 자동 조작 승률은 60판 기준 balanced 40/60, skilled 56/60이다(96px 때는 12판 기준 9/12, 11/12). 조작 실력에 따른 차이가 벌어진 것으로 보이니 난이도를 다시 맞춘다.
- 섬과 길의 축척이 다르다: 섬은 원본 1254px을 가로 1.57배, 세로 1.12배로 늘린 그림이고 72px 축소를 받지 않는다. 길이 섬 밖으로 나가던 문제는 고쳤다(아래 네 줄은 절벽과 HUD 자리라 건설 불가). 타일을 까는 방식은 페이지에서만 시험했는데 축척은 맞아도 격자와 네모 경계가 드러나 채택하지 않았다. 사용자가 지금 섬을 유지하기로 정했다. 그림을 다 올린 뒤에도 거슬리면 새 섬을 검토한다.

## 아이디어

- 마왕을 여러 개 중에 고르는 기능. `demon_lord`를 그리기 전에 몇 종으로 할지 정해야 그림 목록과 비용이 정해진다.
- 정예몹과 보스에 Asteria 직업 그림을 쓰는 안. Asteria는 사용자 본인 게임이다. 보스는 이미 Asteria `boss_fallen_knight`를 그대로 쓰기로 해 `boss_captain`을 만들지 않았다. 정예몹 규칙은 아직 게임에 없다.
- 길을 여러 갈래로 만드는 기능. 지금 경로는 한 줄(`PATH`)만 전제로 짜여 있어 용사 이동과 시설 조준, 건설 칸 계산을 함께 바꿔야 한다. 칸 크기를 정한 뒤에 설계한다.

## 주니어로 옮길 때 확인할 것

1. GitHub 저장소(`juwon3733/dungeon-guard`, 비공개)는 이미 있다. 지금 작업을 올린 뒤 `작업관제소/config.json`의 `repos`에 이 저장소를 추가한다.
2. 주니어는 PixelLab을 그대로 쓸 수 없다. `junior.py`가 `setting_sources=["project"]`로 사용자 범위 MCP를 읽지 않고, `allowed_tools`에도 PixelLab 도구가 없다. 주니어에게 그림 생성을 맡기려면 이 설정을 고쳐야 하고, 아니면 메인 세션이 그림을 만들고 주니어는 코드 연결을 맡는다.
3. 주니어를 켜려면 `작업관제소/start.bat`을 실행한다. 작업 시점에는 꺼져 있었다.
4. 주니어 비용은 API 크레딧에서, 그림 생성 비용은 PixelLab 계정에서 나간다.
5. PixelLab 토큰은 저장소에 넣지 않는다.
